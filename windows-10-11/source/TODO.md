## Автозапуск

- Задача планировщика создаётся для текущего пользователя, имя `memcleaner-<пользователь>`, поэтому второй пользователь не перезаписывает задачу первого.
- XML задачи пишется в UTF-16 с BOM, иначе `schtasks` отвечает «один корневой элемент». В XML заданы `ExecutionTimeLimit PT0S`, запуск и остановка при работе от батареи разрешены, `RunLevel HighestAvailable`, `InteractiveToken`.
- XML создаётся в `%ProgramData%\memcleaner\tasks` со случайным именем. Каталог получает ACL только для Administrators и SYSTEM, проверяются владелец и reparse point, запасного пути в `%TEMP%` больше нет.
- `schtasks.exe` вызывается по полному пути из `System32`, вывод читается в OEM-кодировке, отсутствие файла и `Win32Exception` обрабатываются, зависание убивается по таймауту 15 секунд.
- Автозапуск разрешён только для копии из Program Files: проверяются обе ветки, отсутствие записываемых предков и junction в пути.
- При старте задача больше не пересоздаётся: применение выполняется только при смене настройки. Ошибка включения откатывает переключатель и показывает причину, а не молча выключает настройку.
- Legacy: на Vista и новее используется та же XML-задача с теми же ограничениями, на XP — ключ `Run` текущего пользователя. Путь тоже проверяется по Program Files.
- Осталось: перейти на COM API планировщика (`ITaskService`), чтобы убрать внешний процесс, текстовый разбор ошибок и зависимость от кодировки консоли.

## Безопасность

- Мьютекс и событие активации создаются через `MutexAcl` и `EventWaitHandleAcl` с DACL текущего пользователя и SYSTEM, поэтому второй экземпляр без прав не падает с `UnauthorizedAccessException`.
- Перед `runas` первый процесс освобождает и уничтожает мьютекс, повышенный экземпляр запускается без гонки, а непривилегированный повторный запуск активирует уже открытое окно через событие.
- `DllImport` помечены `DefaultDllImportSearchPaths(System32)`; в legacy это ограничение недоступно на .NET 3.5 и остаётся известным риском.
- `IsTrustedLocation` в WPF проверяет Program Files и Program Files (x86) и отвергает путь, если предок является reparse point.
- Повышенный процесс не доверяет `%APPDATA%`: настройки, история и журнал перенесены в `%LOCALAPPDATA%\memcleaner`, миграция из Roaming выполняется с проверкой reparse point.
- Настройки сохраняются клоном, `Clamp` не мутирует живой объект и не подставляет области очистки по умолчанию.

## Очистка

- Рабочие наборы обрезаются с проверкой токена отмены, свой процесс пропускается, процессы открываются с `PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_SET_QUOTA`.
- `SeProfileSingleProcess` и `SeIncreaseQuota` больше не включаются, `SeDebugPrivilege` включается только на время обрезки рабочих наборов.
- Список ожидания очищается командой `SystemMemoryListInformation` с корректным `command`, список изменённых — отдельной командой. Legacy раньше всегда отправлял `0` и показывал успех.
- Метрика «освобождено» считается по снижению рабочих наборов и приросту доступной памяти, а не по `AvailPhys`, который включает standby.
- Legacy-кэш читается через `GetPerformanceInfo`, а не как максимум `GetSystemFileCacheSize`.

## Интерфейс и настройки

- `_uiVisible` по умолчанию `false`, при старте с `--tray` обновления и анимации не идут.
- Горячая клавиша — `Ctrl+Shift+M`: `Ctrl+Alt+M` перехватывал `AltGr+M` на европейских раскладках. Неудачная регистрация не повторяется на каждое сохранение.
- Язык берётся из `CurrentUICulture`; украинский, грузинский, армянский и азербайджанский больше не мапятся на русский.
- Ошибка в асинхронной команде не закрывает приложение: `DispatcherUnhandledException` пишет журнал и показывает сообщение, работа продолжается.
- `MinimizeToTray` теперь означает «закрывать в трей»; выход из меню трея не выключает настройку.
- Слушатель активации использует `Dispatcher.BeginInvoke`, журнал пишет полный стек, тексты журнала на английском.
- Удалены неиспользуемые ключи локализации, включая `fatalError`, `resultFailed` и `resultPartial`.

## Legacy

- Автоочистка больше не срабатывает через 5 секунд после запуска: отсчёт идёт от текущего времени.
- Порог получил гистерезис 5 процентов и флаг взведения, поэтому очистка не повторяется каждые `CooldownMinutes` при постоянно высокой загрузке.
- Выход из трея выставляет отдельный флаг и не выключает `MinimizeToTray`.
- Сообщение об ошибке автозапуска не исчезает сразу после `SaveSettings`.
- Подсказка трея обновляется и при скрытом окне.
- `Autostart.Apply` выполняется в фоновом потоке, интерфейс не блокируется на время `schtasks`.
- Манифест `asInvoker`, повышение прав выполняет сам процесс; второй запуск не показывает UAC и активирует открытое окно.
- Сообщение о повторном запуске переведено: язык применяется до любых сообщений.
- Windows 5.2 определяется как «Windows XP x64 / Server 2003», а не «Windows 2000».
- Журнал ограничен 200 записями при чтении и записи, настройки читаются с лимитом 64 КБ, запись атомарная через `File.Replace` и уникальный временный файл.
- Исключения процессов разбираются по запятой, точке с запятой и переводу строки.
- Рабочие наборы открываются с минимальными правами, а не `PROCESS_ALL_ACCESS`.
